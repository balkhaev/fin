# BTC Pullback Flow — проверка цели +500% в год

**Гипотеза не прошла проверку. `target_achieved=false`, `live_ready=false`.**

Изолированный research/paper модуль FIN. Нет API-ключей, подписания запросов,
отправки ордеров, подключения к production scheduler или разрешения плеча.
Прибыль более 500% в год не получена. Отрицательные результаты сохранены.

## Два разных уровня реализации

`engine.py` реализует исходный сигнал: закрытые 5m EMA20/EMA50, VWAP20, ATR14,
предыдущие/текущие 10 секунд исполненных сделок, отсутствие нового экстремума за
5 секунд, post-only, 15s TTL, частичные исполнения, консервативную оценку очереди
L1, стоп/цель/8 минут, funding и ограничение риска. Это paper-модель: полная
очередь неизвестна, protective exit смоделирован немедленным, latency/cancel
races не сертифицированы. **Полный год trade/BBO replay не выполнен.**

`study.py` — отдельный предварительный тест на 1m свечах: минутный flow/stall
вместо 10s/5s, next-open market/taker вместо post-only. Его цифры **не являются
точным бэктестом исходного скальпера** и не доказывают убыточность всех вариантов
точного сигнала. Они не дают оснований обещать прибыль или допускать live.

`download.py` загружает реальные первичные Binance USD-M BTCUSDT архивы и
CHECKSUM. Пропуски, изменившиеся checksum и funding не заменяются нулями.

## Расходы и причинность

Основной сценарий: комиссия 0.05% на вход и выход, проскальзывание 0.01% с
каждой стороны, реальный funding. Это условный OKX-like taker cost stress на
ценах Binance, **не бэктест на OKX**. MEXC API cost stress: 0.08% на каждую
сторону, также не одноплощадочная проверка. Современные тарифы применены ко всей
истории как сценарии, не как точная реконструкция прошлых тарифов.

Сигнал только по закрытым данным, вход на следующем open, stop-first при
неизвестном порядке high/low, неблагоприятное исполнение gaps. Каждая сделка
сверяется с денежным ledger. Время intrabar exit — конец свечи, точный момент
неизвестен. Все стрессы сохраняют один cost gate: высокие комиссии не скрываются
исключением входов. Sizing и дальнейшее исполнение могут различаться.

Funding timestamps имеют до 31ms смещения. Проверяется полное расписание,
допускается до 5s jitter, событие сопоставляется своей минуте. В эту минуту
входы запрещены. Платёж рассчитывается по minute-open trade price, **не по
исторической mark price**. Налоги и фиксированные операционные расходы не учтены.

## Воспроизведение

Python 3.13, отдельное окружение; запуск из корня репозитория:

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r research/btc_flow/requirements.txt
python -m pytest -q tests/test_btc_flow.py
python -m research.btc_flow.download --out btc-evidence
python -m research.btc_flow.study --data btc-evidence --out btc-flow-report
```

`results/summary.json` — зафиксированный компактный результат. Полные результаты
36 кандидатов, annual CSV, trade ledgers, daily equity и manifest создаются в
отчёте и публикуются как artifact workflow `BTC Flow validation`. Архив данных
можно восстановить публичным downloader после истечения срока Actions artifact.
CI сравнивает повторный replay с зафиксированной сводкой, но успех CI означает
воспроизводимость, **не прибыльность**.

Для исходной событийной модели нужен реальный same-venue JSONL, а не выдуманные
сделки из минутных свечей:

```bash
python -m research.btc_flow.engine --events recorded-events.jsonl --out paper-replay.json
```

Первая строка: `{"type":"metadata","same_venue":true,"funding_complete":true}`.
Эти флаги — утверждения поставщика, модуль не доказывает их сам. Далее в порядке
`ts` идут `quote` (bid, ask, bid_qty, ask_qty), `trade` (price, qty,
buyer_aggressor boolean), `bar` (end, high, low, close, volume, quote_volume) и
`funding` (rate, mark). Миллисекунды UTC, quantity в базовом BTC; контрактные
размеры должен преобразовать адаптер данных. Нужен прогрев 53 закрытых 5m баров.
Устаревший BBO на защитном выходе помечает `execution_incomplete=true`, а не
создаёт выдуманное исполнение. Реальная отправка ордеров отсутствует.

## Исправления и ограничения

Первый инженерный прогон признан недействительным: откат потреблялся до cost
gate, а funding ошибочно требовал точного совпадения миллисекунды. Исправлены
loader и arming, cost gate зафиксирован во всех стрессах. Первый прогон сохранён
в приложенном downloadable bundle с пометкой INVALID, не используется в итогах.
37 unit/regression tests покрывают причинность, next-open, stop-first, gaps,
fees/funding, ledger, rearm, post-only rejection, partial fills, latency/TTL,
очередь, stale data и полноту manifest. Это не доказательство торгового edge.
