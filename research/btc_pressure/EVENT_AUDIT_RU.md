# BTC Pressure: событийная проверка цели +500% — 5 сентября 2026

**Цель +500% годовой прибыли не доказана.** В этой итерации выполнена проверка
рыночных сигналов на трёх заранее выбранных сутках, исправлены ошибки paper-ledger
и усилена идентичность калибровки. Это не годовой бэктест счёта и не реальная торговля.
Предыдущие свечные отрицательные результаты и первоначальная неполная трёхминутная
запись остаются отдельными экспериментами, их метрики новой модели не приписываются.

## 1. Что изменилось относительно предыдущей проверки

Вместо записи с недоступными REST endpoint получены публичные исторические CSV
Tardis для BTCUSDT. Первые сутки месяца доступны как публичные образцы без API-ключа.
Выбор дат зафиксирован до просмотра записей в `event_audit_protocol.json`, коммит
`06d89feaef8b55ab67c35e41e30b0cbe5f9783ec`. Даты: **2025-09-01, 2026-03-01,
2026-09-01 UTC**. Это три суток, а не год: разница между крайними датами не означает
непрерывное наблюдение. Часть более старой истории уже использовалась в свечных
исследованиях; весь эксперимент нельзя назвать pristine OOS.

Получены 18 файлов: Bybit linear trades, book_snapshot_5, liquidations,
derivative_ticker; Bybit spot trades; Binance spot trades — для каждой даты.
Исходная загрузка: Actions run `33954086998`, artifact `9965775587`.
Всего **27 398 297 записей**, **237 491 пригодных секундных состояний** после
прогрева и проверок давности данных. Все файлы проверены SHA-256; дубли ID сделок
и нарушения порядка receive time не обнаружены. Хеш доказывает неизменность
скачанных байтов, не независимую подлинность источника или полноту всего рынка.

`event_sources.json` фиксирует точные хеши и размеры. Downloader прекращает
проверку при изменении источника и не обходит 401/403/451. Покупки и API-ключи
не использованы. CI может повторно скачать те же публичные файлы и не зависит
от срока хранения первоначального Actions artifact.

## 2. Метод и границы результата

`event_study.py` использует полностью закрытые секундные корзины **времени
получения**, сохраняя биржевое время отдельно. Минутные OHLC строятся из реальных
сделок с ограниченной задержкой и становятся известными не раньше конца минуты
плюс пять секунд. Поздние сделки не дорисовывают прошлый вход. Стакан берётся
только из снимка, полученного до момента сигнала. Событийные автоматы из
`strategy.py` не перенастраивались по результатам этой выборки.

Это специальный архивный профиль, а не точная копия V1: он принимает решения
на границе закрытой секунды, тогда как исходный runner — на первом сообщении
секунды; свечи восстановлены из принятых сделок, а не взяты из kline-потока.
CSV не содержит полного журнала разрывов подключения. Часы разных сборщиков
могут расходиться и не представляют задержку сети пользователя. Давность
данных проверяется, но абсолютная полнота источника этим не доказана.

В нормализованном Tardis Bybit liquidation CSV сторона уже преобразована в
сторону принудительного **ордера**. `sell` — давление продаж. Повторное инвертирование
по правилу сырого Bybit `S=Buy` перевернуло бы сигнал. Это проверено по первичному
исходнику mapper Tardis; цена ликвидации не используется как цена исполнения.

Для каждого сигнала рассчитан отдельный диагностический результат входа по
первой доступной лучшей встречной котировке после 250 мс и выхода через 30 секунд,
5 минут и 30 минут с дополнительной задержкой 250 мс. Учтены спред, **taker-комиссия
0,055% на каждую сторону** и **slippage 0,01% на каждую сторону**. Это фиксированные
исследовательские расходы, не подтверждённый исторический тариф пользователя.

**Это контрфактические taker-markout, не закрытые сделки общего счёта.** Здесь нет
очереди реальной maker-заявки, stop/target сопровождения исходной стратегии,
объёмного исполнения и взаимного исключения перекрывающихся идей. Сигналы могут
перекрываться; результаты нельзя складывать или капитализировать как доходность.
Для `spot_trend`, у которого исходно пассивный вход, это особенно важное отличие.

Пересечение времени funding делает оценку неполной: предсказанная ставка из
`derivative_ticker` не заменяет фактическое начисление. Из 363 оценок 347 имеют
достаточные конечные котировки без пересечения funding, 12 помечены
`funding_unpriced`, 4 не имеют полного горизонта до конца записи. Пропуски не
подставлены нулями. Годовой CAGR намеренно отсутствует.

Средний результат после расходов, **базисные пункты номинала**; 1 б.п. = 0,01%.
Это не проценты капитала счёта.

|---|---:|---:|---:|
| Каскад, все оценимые сигналы | -10,0351 (90) | -12,2495 (88) | -12,2098 (82) |
| Спотовое подтверждение, все оценимые | -12,6872 (30) | -7,3209 (30) | -2,2264 (27) |
| Каскад, только прошедшие ценовой фильтр | -9,3692 (5) | -26,5025 (5) | -39,8517 (5) |

Число в скобках — количество оценимых контрфактических входов. Все spot_trend
прошли ценовой фильтр, поэтому их фильтрованная строка совпадает с основной.

Положительные подвыборки не скрыты: у spot_trend при выходе через 30 минут
2025-09-01 среднее +6,9365 б.п. по 12 оценкам, 2026-09-01 +5,9732 б.п. по 11,
но 2026-03-01 -52,2640 б.п. по четырём. Общее среднее отрицательное. Выбор только
двух удачных суток задним числом не доказывает преимущество. Трёх дат недостаточно
для надёжной оценки хвостовых рисков, сезонности или годового результата.

**Вывод узкий:** у данного набора сигналов при фиксированных рыночных входах и
выходах преимущество после расходов не выявлено. Это не доказательство убыточности
всех вариантов полноценного BTC Pressure с пассивным исполнением и сопровождением.
Однако эти данные не обосновывают увеличение плеча или заявление +500%.

## 5. Ошибки, воспроизведённые и исправленные до публикации

**Funding после закрытия позиции.** Старый broker начислял платёж только текущей
позиции. Когда сообщение приходило после её закрытия, стоимость могла потеряться.
Теперь запоминается владелец и объём позиции на момент начисления, платёж относится
к соответствующей открытой или закрытой сделке, обновляются cash/net/net R.
Частичное закрытие после события не уменьшает прежнее обязательство. Повторный
платёж не списывается дважды, конфликтующий дубликат блокирует пригодность отчёта.

Поздняя корректировка cash **не сертифицирует прежнюю просадку и решения**.
Для неё выставляется `funding_time_drawdown_verified=false`, оценка качества
счёта блокируется. Неизвестное начисление остаётся обязательством даже после
закрытия позиции. Это честная бухгалтерская защита, не законченная интеграция
годовой истории settlements или margin/liquidation engine.

**Отмена по TTL.** Раньше подтверждение отмены отсчитывалось от первого сообщения
после истечения заявки, что могло искусственно продлить её жизнь. Теперь крайний
момент привязан к `expires + latency`, независимо от наличия сообщения ровно в TTL.

**Риск в глубокой просадке.** При небольшом исходном риске старая ветка DD>=5%
могла повысить риск относительно DD>=3%. Теперь дальнейшая просадка не увеличивает
его. Лимиты — исследовательские настройки, не гарантия ограничения реального убытка.

**Калибровка.** Допуск теперь связан с SHA-256 точного кода нормализации, сигналов,
исполнения и replay. Старые gate-v1 не принимаются. Infinity, NaN и неверные типы
статистики не могут разрешить вход. Обучающие отчёты должны быть полными, реальными,
закрытыми и относиться к текущей модели. Поддельный JSON не становится независимым
доказательством происхождения; внешний аудит источника по-прежнему необходим.

## 6. Проверки и воспроизведение

Локально **109 тестов прошли: 89 прежних и 20 новых**. Три новых регрессии сначала
воспроизведены как падающие на предыдущем коде. `event_source_lock.json` фиксирует
побайтный состав локально проверенных файлов. Новый workflow отдельно выполняет
полный корневой test suite и повторяет историческое исследование, сравнивая
численные результаты с `event_audit_summary.json`. Прохождение CI означает
воспроизводимость, не прибыльность; актуальный статус берётся из Actions artifact.

Python 3.13, запуск из корня репозитория или полного пакета:

```bash
python -m pip install -r research/btc_pressure/requirements-event.txt
python -m pytest -q tests/test_btc_pressure.py tests/test_btc_pressure_audit.py
python -m research.btc_pressure.download_event_samples --out event-samples
python -m research.btc_pressure.event_study --data event-samples --out event-report
```

Нужен новый каталог результата; предыдущие данные не перезаписываются.
Сетевой доступ требуется только downloader, не расчёту. Исходные CSV занимают
около 394 МБ сжатыми, рабочая память существенно больше. Выход: все сигналы,
markout CSV, по-сессионные счётчики и JSON с ограничениями.

Результат допуска:

```text
sample_days              3
continuous_years         0
account_return_pct       null
cagr_pct                 null
annual_test_complete     false
target_achieved           false
live_ready               false
```

Реальных ордеров, подписания запросов, покупок данных и изменения работающего
scheduler нет. Годовая прибыль более 500% в этой итерации не получена.
