# Точное повторение из приложенных архивов

Для проверки опубликованных цифр используйте сохранённые исходные байты,
а не повторную загрузку с новым временем acquisition в manifest.

Распакуйте **BTC_Spot_Regime_Verified.zip** и **BTC_Spot_All_Policy_Tests.zip**
в один новый общий каталог. Они создают разные подкаталоги: `spot-data`,
`spot-report`, `spot-delivery`, `followup` и `delivery`. Исходные результаты
не удаляются. `delivery` содержит оба исследовательских модуля.

Из этого общего каталога:

```bash
cd delivery
python -m pip install -r requirements.txt
python -m pytest -q tests/test_btc_spot*.py
python -m research.btc_spot_regime.study --data ../spot-data --out ../original-replay-new
python -m research.btc_spot_followup.study --data ../spot-data --original ../spot-report --out ../followup-replay-new
```

Python 3.13 соответствует проверенной среде. Названия новых каталогов результата
должны ещё не существовать. `--original ../spot-report` указывает на первоначальный
расчёт из архива; его SHA проверяется до расширенной диагностики. Это не разрешение
подставить произвольный отчёт или заменить проигравшие строки.

В полном репозитории основной новый сбор можно запускать с `--download` как
в README. Он создаёт новый manifest и новый набор свидетельств; он не обязан
иметь SHA первоначального результата даже при совпадающих ценах. Расширенная
проверка сознательно привязана к сохранённому первоначальному результату.

Команды только скачивают публичные данные либо рассчитывают историческую
симуляцию. Ни одна не читает ключи и не отправляет реальные ордера.
