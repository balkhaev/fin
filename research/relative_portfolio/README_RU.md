# BTC-направление и относительная пара в одном счёте

Дополнительный эксперимент объявлен после получения результатов отдельных
фьючерсных моделей. Поэтому это исследование новой композиции на известной
истории, **не независимое подтверждение победителя**. Параметры каждого
дополнительного сравнения фиксировались до его вычисления, но общая программа
уже знала, что относительный тренд имел прибыльные и убыточные годы.

Гипотеза: покупать BTC в подтверждённом медленном восходящем режиме, а вне него
использовать относительное движение ETH/BTC. Это не то же самое, что пытаться
покупать отдельные растущие монеты при слабом рынке. Парная позиция содержит
одновременно длинную и короткую фьючерсную ногу.

Основной `switch_half` использует существующее правило направления BTC:
последнее полностью закрытое дневное значение выше SMA200 и выше значения
63 дня назад. До получения 201 полных дневных баров торговли нет. Дневной
результат становится доступным только в следующую полночь UTC; текущий
незавершённый день не считается известным заранее.

При положительном режиме целевая позиция +0.5 BTC-номинала счёта; при
отрицательном — половина существующих знаковых целей `pair_momentum720`.
Последние при ненулевом сигнале означают примерно +0.25 одной ноги и −0.25
другой. Это предел целевого номинала при входе, не постоянный предел реальной
экспозиции или потери. Количества между сменой знакового состояния не
перебалансируются каждый час, как и в исходном расчётном механизме.

Сравниваются пять заранее названных вариантов: только BTC-core, только пара
на половину номинала, переключение, одновременная смесь четвертей и только
парный блок вне положительного режима. Сигналы исполняются в **одном счёте**,
с взаимным зачётом знаковых позиций, комиссиями и funding. Прибыль независимых
счетов не складывается в синтетическую доходность комбинации.

Во всех 41 отчётах одинаковый исходный капитал и существующие правила
исполнения. Основной вариант и BTC-core дополнительно проверяются при удвоенных
расходах, задержке на ещё один час, капитале 1 000 USDT и на семи независимых
началах годового счёта. Эти годовые интервалы частично перекрываются.
Выгодный вариант не переименовывается задним числом в первоначальную гипотезу.

Существующий `account.py` не изменён. Известный дефект оценки неиспользуемой
монеты с отсутствующей mark price остаётся неисправленным после блокировки
записи. Здесь используются отдельно сверенные реальные данные, в которых
пропуски дополнены официальными суточными архивами, а не выдуманными ценами.
Это позволяет проверять данные сценарии, но не делает механизм пригодным для
работы с произвольными новыми пропусками или реальными деньгами.

Все результаты — сценарии исторического линейного фьючерса, а не замер
реального исполнения. Funding использует наблюдённые ставки с приближением
mark price к открытому значению часа. Ступени биржевой маржи и реальная
синхронность двух исполнений не восстановлены полностью. Налоги, инфраструктура,
контрагент и риск USDT также не включены. Сравнение с прежней девятиактивной
спотовой защитой не считается равным сравнением инструментов и расходов.

Повторение из полного вычислительного пакета:

```bash
cd current_code
python -m pip install -r requirements.txt
python -m research.relative_portfolio.study --source ../reconciled --out ../composition-new
```

В каталоге `reconciled` должны быть сохранены исходный результат из 62
пересчитанных сценариев и подпапка `supplemented/reconciled` с часовыми данными.
Скрипт проверяет их идентификаторы и исходники расчётного механизма. Вывод
пишется только в новый каталог. Это не команда запуска реальной торговли.
